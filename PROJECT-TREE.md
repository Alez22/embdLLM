## What we are NOT writing (already there)

These exist upstream and we reuse without rewriting:
- `llm_client.py` — multi-provider (Groq / OpenRouter / Anthropic via LiteLLM)
- `test_tracker.py` — persistent tracker + content hash (Phase 8 extends, not creates)
- `sensitivity.py` — variance machinery (Phase 7 reuses)
- `runner.py` checkpoint — crash-recovery resume (Phase 8 builds the durable layer beside it)
- 5-layer evaluator, scorer, reporter, CLI scaffold, Docker pattern (Dockerfile.stm32 as template)

## Modification footprint

- **Core modules touched: 8** (cli, runner, evaluator, models, test_tracker, scorer, reporter, sensitivity)
- **New core modules: 4** (check_utils_nxp, review, gencache, gradecache)
- **New cases: ~28** (12 generation + 9 task-type + 7 probe)
- **New docs: 6**, **New tests: 4**

Most of the volume is *new case content* (data, not code). The actual code change
is concentrated in ~8 modified modules + 4 new ones — a contained, reviewable surface.
